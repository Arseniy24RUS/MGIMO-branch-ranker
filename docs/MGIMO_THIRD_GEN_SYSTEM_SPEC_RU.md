# ТЗ для Codex App: MGIMO Branch Ranker / Student Attraction — система третьего поколения

## 0. Роль Codex App

Ты работаешь не как один разработчик, а как автономная команда: архитектор данных, методолог, frontend-инженер, картограф, QA-инженер, редактор русского языка и независимый reviewer. Используй Codex CLI, subagents, PlaywrightQA, Python QA и, если доступно, Agents SDK + Codex MCP. Не останавливайся после первой реализации. Выполняй цикл:

```text
реализация → автоматические тесты → ревью subagents → исправления → повторная проверка
```

Работа считается завершённой только когда:

```text
1. Все Python QA проходят.
2. Все Playwright-тесты проходят в Chromium, WebKit, mobile Chromium, mobile WebKit.
3. Нет console/pageerror, NaN, undefined.
4. Все reviewer scorecards дают 10/10.
5. Дашборд понятен руководителю МГИМО за 30 секунд без устной инструкции.
```

Если достигнут лимит времени, не объявляй успех. Сохрани список незакрытых blockers.

## 1. Главная продуктовая цель

Нужно создать строгий, простой и доказуемый dashboard мирового уровня. Он должен отвечать на два разных вопроса:

1. Где приоритетно открывать или развивать зарубежное присутствие МГИМО?
2. Из каких стран приоритетно привлекать иностранных студентов в МГИМО в Москве?

Эти две задачи нельзя смешивать. Для них нужны две разные модели и две связанные страницы/слоя интерфейса.

## 2. Страница 1: приоритеты зарубежных филиалов

### 2.1. Что убрать

Полностью убрать:

- дату вида «Данные на 4 июн. 2026 г.» из шапки;
- прежнюю управленческую полосу с выбранной страной, статусом, режимом, аргументом, риском и следующим шагом;
- все альтернативные режимы расчёта приоритетов;
- любые упоминания того, что Вьетнам исключён из общего рейтинга или идёт отдельным привилегированным треком;
- pipeline-бонусы в итоговом индексе.

### 2.2. Что оставить и усилить

Оставить один итоговый индекс. Это просто основной расчёт.

Вьетнам должен быть в общем рейтинге. Его статус можно показывать как «В подготовке», отдельным цветом в таблице и на карте. Формулировка:

```text
Статус «В подготовке» не даёт бонуса в итоговом индексе и не исключает страну из общего рейтинга.
```

Если Вьетнам занимает первое место без pipeline-бонуса, это нужно показать как независимое статистическое подтверждение выбранного направления.

### 2.3. Редактируемые веса

Наверху должна быть компактная панель весов семи факторов:

```text
I_MARKET, I_PROGRAM, I_RUSCOMP, I_ECO, I_FIN, I_FEAS, I_HRSTRAT
```

На desktop показывай компактную строку с весами и кнопку «Изменить веса». Полные слайдеры — в accordion/modal. На mobile слайдеры скрыты по умолчанию.

Пользователь может менять веса. Рейтинг пересчитывается на лету по той же формуле. Должны быть:

- «Сбросить веса»;
- «Скопировать ссылку с текущими весами»;
- нормировка весов к сумме 1;
- предупреждение: «При изменении весов пересчитываются баллы и места; категории рекомендаций показаны по исходной классификации» — либо реализовать пересчёт категорий по прозрачным правилам.

### 2.4. Доказательная методика факторов

Каждый фактор должен иметь скрытый блок «Как считается?»:

- красивая формула;
- обычное русское объяснение;
- полный список входных показателей;
- официальное название показателя в первоисточнике;
- код показателя, если есть;
- источник;
- реальный год наблюдения;
- raw value;
- normalized value;
- вес внутри фактора;
- статус observed / imputed / modelled;
- метод нормировки.

Для каждой страны должно быть ровно семь вкладок по семи факторам. Внутри вкладки показываются только данные, реально участвовавшие в расчёте соответствующего фактора.

Переименования:

```text
I_PROGRAM: «Программно-отраслевая релевантность»
I_RUSCOMP: «Нормативно-партнёрский контекст»
```

Не использовать «соответствие МГИМО» и «совместимость» без раскрытия, потому что это звучит как экспертная оценка страны.

## 3. Демография

Главное правило: отображаемые демографические данные должны быть согласованы и собраны из обязательного WPP-источника. Нельзя показывать прогнозную пирамиду из одного массива и population_total из другого без нормировки.

### 3.1. Предпочтительный источник

Обязательный источник — UN WPP 2024 age-sex estimates/projections. Скачать через UN Data Portal API или официальный bulk dataset. Если WPP-строки для страны нет, сборка не публикует демографический блок для этой страны.

### 3.2. Визуализация

Оставить только когорту 15–24. Убрать селектор 17–24 / 15–29.

Сделать один сильный график:

- верхняя линия — общая численность населения;
- внутренняя заливка/столбцы — население 15–24;
- факт и прогноз различаются стилем, прозрачностью и подписью.

Половозрастная пирамида:

- мужчины слева, женщины справа;
- выделена только группа 15–24;
- orientation: стандартная демографическая пирамида;
- подпись: «Когорта 15–24 используется в расчёте рыночного фактора».

### 3.3. Проверка

Добавить тест:

```text
sum(ageSexPyramid all groups) ≈ demographySeries.population_total
sum(ageSexPyramid 15–19 + 20–24) ≈ demographySeries.pop_15_24
```

для всех стран и всех лет. Допуск не выше 1%. Если выше — нормировать или пересобрать из одного источника.

## 4. Страница 2: привлечение иностранных студентов в МГИМО

Это новая самостоятельная модель. Она не должна копировать модель филиалов и не должна использовать филиальную financial student ramp как поток студентов в Москву.

### 4.1. Model: SAI_MGIMO_V3

Цель: оценить приоритетность стран для привлечения иностранных студентов в МГИМО в Москве.

Агрегация: простая взвешенная сумма 0–100. Здесь допустима частичная компенсация: крупный и быстрорастущий молодёжный рынок может быть стратегически важен даже при невысокой платёжеспособности.

Hard filters применяются отдельно:

```text
unfriendly_430r, domestic_russia, non_sovereign_or_special
```

Витрина должна иметь два режима:

1. Страны с индексом — hard-filter страны и страны без полного набора открытых рядов исключены из рейтинга.
2. Справочно все страны — hard-filter страны и страны без индекса остаются на карте со штриховкой и без места.

### 4.2. Формула SAI_MGIMO_V3

```text
SAI = 100 × (
  0.50 × A_YOUTH_OPPORTUNITY
+ 0.16 × A_OUTBOUND_MOBILITY_UIS
+ 0.12 × A_LEGAL_PARTNERSHIP_CONTEXT
+ 0.08 × A_PROGRAM_RELEVANCE
+ 0.06 × A_AFFORDABILITY_ACCESS
+ 0.04 × A_DIGITAL_REACH
+ 0.04 × A_DATAQ
)
```

#### A_YOUTH_OPPORTUNITY

```text
0.70 × N(log(pop_15_24_latest))
+ 0.30 × N(pop_15_24_growth_10y_pct)
```

Этот блок намеренно имеет вес 0.50, чтобы численность молодежи 15–24 и ее фактическая динамика были основной частью студенческого индекса. Региональные бонусы не применяются.

#### A_OUTBOUND_MOBILITY_UIS

Используется официальный ряд UNESCO DataHub UIS `uis006`, indicator `MOR.5T8.40510`:

```text
N(outbound_mobility_ratio_tertiary)
```

Если UIS-строка отсутствует, страна не получает студенческий индекс и практическое место.

#### A_LEGAL_PARTNERSHIP_CONTEXT

Компонент сохраняется только как справочный technical trace с нулевым весом. Жесткие фильтры не добавляют и не вычитают баллы: они определяют право страны получить индекс.

#### A_PROGRAM_RELEVANCE

Компонент сохраняется только для совместимости схемы с нулевым весом. Студенческий индекс не копирует программно-отраслевой блок филиальной модели.

#### A_AFFORDABILITY_ACCESS

```text
N(log(GDP per capita PPP))
```

Вес небольшой, чтобы платёжеспособность не вытесняла демографически перспективные страны. Для МГИМО возможны гранты, квоты, целевой набор и подготовительные программы.

#### A_DIGITAL_REACH

Доля пользователей интернета. Это канал цифрового рекрутинга и коммуникации с абитуриентами.

#### A_DATAQ

Доля заполнения обязательных открытых рядов. Если обязательный ряд отсутствует, страна не получает индекс.

### 4.3. Потоковая карта

Фактические дуги потоков рисуются только при наличии фактического открытого странового источника. Отдельно допускается тонкий полупрозрачный слой направлений по SAI_MGIMO_V3 от стран с индексом к Москве; он не является численностью студентов и должен иметь переключатель показа.

Если страновые данные МГИМО о фактических иностранных студентах отсутствуют, писать:

```text
Фактические страновые потоки студентов МГИМО не загружены из открытого источника; стрелки показывают направления по рассчитанному индексу, а не численность студентов.
```

`student_flows_observed.csv` должен иметь заголовки даже при отсутствии строк.

## 5. Autonomous review loop

Добавить в проект:

```text
codex/prompts/MGIMO_DASHBOARD_V3_MASTER_TZ.md
codex/reviewers/*.md
codex/agents/run_codex_iterative_review_loop.py
scripts/dashboard_review_score.py
scripts/validate_demography_v3.py
```

Использовать subagents:

- executive_reviewer;
- methodology_reviewer;
- data_provenance_reviewer;
- student_attraction_reviewer;
- visual_ux_reviewer;
- qa_accessibility_reviewer;
- russian_editor_reviewer.

Каждый reviewer возвращает JSON scorecard. Итоговый успех только если все score_0_10 = 10 и все тесты проходят.

## 6. QA acceptance

Обязательные тесты:

- нет токенов альтернативных режимов в UI/методике;
- Вьетнам в общем рейтинге со статусом «В подготовке»;
- статус «В подготовке» не даёт бонуса к индексу;
- веса меняются, рейтинг пересчитывается;
- семь вкладок факторов;
- каждая вкладка содержит формулу, source, year, raw, normalized, weight;
- реальные годы наблюдений не заменяются везде на 2026;
- демография согласована с пирамидой;
- пирамида только 15–24;
- студенческий слой использует SAI_MGIMO_V3;
- африканские быстрорастущие страны видны в верхней группе студенческого рейтинга;
- hard-filter страны не попадают в practical top без предупреждения;
- карта потоков не выдаёт модельный потенциал за фактический поток;
- node_modules не входит в финальный архив.
